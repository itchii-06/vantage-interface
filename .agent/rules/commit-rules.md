# コミットルール

## メッセージ形式

Conventional Commits に従い、英語で記述する

```
{type}: {変更内容の説明}
```

### type の一覧

| type    | 用途                                                       |
| ------- | ---------------------------------------------------------- |
| `feat`  | 機能追加・機能変更                                         |
| `fix`   | バグ修正                                                   |
| `chore` | 機能に影響しない変更（設定・ドキュメント・リファクタなど） |
| `wip`   | 作業中（レビュー不要のコミット）                           |

---

## コミットの粒度

- 1 コミット 1 責務（複数の変更を混ぜない）
- 以下は必ず別コミットに分ける

## やってはいけないこと

- 日本語で記述すること
- 自動生成ファイルだけを単独でコミットする（生成元のソースと同じコミットに含める）
- `fix: 修正`など変更内容が不明なメッセージをつける
- 複数機能の変更を 1 コミットにまとめる
